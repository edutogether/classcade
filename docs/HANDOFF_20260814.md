# CLASSCADE 핸드오프 — 2026-08-14

## 1. 이 앱은 뭐 하는 앱인가

**CLASSCADE** — 교실 NBTI 기반 몰입형 교육 게임. 교사가 자기 교실 성향을 16문항으로 진단받고, 결과 유형에 맞춘 교실 게임/놀이를 추천받는 웹 앱. React 19 + TS + Vite 7 + Firebase, Vitest.
배포: `https://edutogether.github.io/classcade/` (GitHub Pages Actions, `main` 푸시 시 자동 배포).

## 3. 이번 세션에서 완료한 것

- **로딩 화면 전면 개편**: `loading-master-v6` 아트로 교체, 제목/부제/점3개/진행바를 전부 라이브 DOM으로 전환(예전엔 이미지에 구운 한글 텍스트라 흐릿했음). 좌표는 `src/components/prep/ArtLoadingScreen.tsx`의 `ART`/`TEXT` 상수로 관리 — art-pixel 좌표계를 cover-fit 스케일로 화면에 투영하는 방식.
  - 반복 피드백으로 제목/점3개/부제 위치를 여러 차례 재조정 (점3개는 바 위→바와 부제 사이로 이동, 제목은 로고와의 간격, 부제는 바와의 간격 조정 등). 최종 값은 파일의 `TEXT` 상수 참고.
- **NBTI "다시 탐색하기" 버튼**이 인터루드 없이 즉시 전환되던 버그 수정 — 다른 모든 화면 전환과 동일한 로딩 인터루드(`reviewing` state)를 거치도록 통일. (구현 중 훅 순서 위반 버그를 직접 만들었다가 ESLint로 잡아서 고침 — early return 앞으로 훅을 옮겨야 했음.)
- **헤더 CLASSCADE 로고 글로우 완화** — 너무 각지고 강했던 것을 불투명도 낮추고 블러 키우고, 워드마크 쪽은 사각형→타원형으로 바꿔 더 은은하게.
- **프리즈 완료**: `classcade-freeze-20260814` 태그 + `.githooks/pre-push`(portal/googler와 동일 패턴)로 태그 보호. 훅이 실제로 삭제를 막는지 직접 검증까지 완료.
- 모든 변경은 tsc/eslint/vitest/build 통과 확인 후 `feature/front120-entry-flow-v1` → `main` merge(`--no-ff`) → push → `gh run list`로 배포 성공 확인까지 매번 완료.

## 5. 주의사항

- **이 저장소는 현재 프리즈 상태(`classcade-freeze-20260814`)다.** 이 태그는 `.githooks/pre-push`로 삭제/이동이 막혀 있음 — 새로 클론했다면 `git config core.hooksPath .githooks`로 보호를 활성화해야 함. 프리즈 이후 추가 작업은 새 커밋으로 쌓으면 되고, 태그 자체를 건드릴 필요는 없음(막히기도 함).
- **CNAME/커스텀 도메인 절대 다시 추가 금지** — 이 앱의 공식 주소는 `edutogether.github.io/classcade/`뿐이다. `edutogether.kr`은 별도 portal 저장소 소유.
- **이미지/에셋 압축은 항상 제일 마지막 순서**로 — 이번 세션에 이미 PNG→WebP 전량 전환은 끝났음(91MB→7.7MB), 새 아트 추가 시에만 해당.
- `ArtLoadingScreen.tsx`의 `ART`/`TEXT` 좌표는 `loading-master-v6.webp`를 기준으로 픽셀 스캔한 값이다. **로딩 아트를 교체하면 이 좌표들을 반드시 재측정**해야 한다 (재측정 안 하면 텍스트가 바 프레임을 벗어나거나 겹침).
- UI 변경은 tsc/eslint/vitest 통과만으로 끝내지 말고 실제 브라우저(Puppeteer/Claude Browser)로 확인할 것 — 이번 세션 내내 그렇게 진행했고, 실제로 그 과정에서 버그(훅 순서 위반, 버튼 onClick 미연결)를 잡아냈다.
- 배포 확인은 `gh run list --workflow deploy-pages.yml --limit 1`로 `completed/success` 뜨는 것까지 보고 끝낼 것.
